# Open Questions

This is the short list of questions most likely to affect the first design iterations.

## Product

- What should the app help a user do in the first 30 seconds after opening it?
- Is the primary motivation personal progress, collecting classes, completing quests, or some combination?
- How silly should names and flavor text be before they undermine trust in the fitness data?

## Progression

- What should determine XP for running, lifting, cycling, and activities that do not share a natural unit?
- Should users be able to respec or rename a class?
- What happens when an activity is edited, duplicated, or removed at the source?
- Should passive and active levels appear as two adjacent stats or as separate screens?
- How often should active performance decay as the six-month window moves forward?
- Should a user's peak be permanent, seasonal, or resettable?

## Competition

- What exactly is being ranked: current active level, peak active level, cumulative level, or a combination?
- How are neighborhood boundaries defined, and how does the app handle users who do not want to disclose location?
- Should leaderboard participation be opt-in, private by default, or pseudonymous?
- What safeguards prevent identifying individuals in tiny geographic areas?

## Friends

- Is the Friends entry point a home card, a social section on the class panel, or a secondary action?
- Can users browse a friend's full skill history, or only current levels and selected achievements?
- Which friend data is visible by default, and can each friend control visibility separately?
- Should friend comparison use the same skill-specific ranks as public leaderboards?

## Avatar and rewards

- Are loot drops purely cosmetic, or can some items communicate accomplishments without affecting performance?
- What drop rate makes rewards exciting without becoming noisy or compulsive?
- Should achievement rewards be guaranteed while activity drops remain random?
- Can users trade, gift, or duplicate cosmetic items?

## UX

- Is a character dashboard more motivating than a conventional fitness dashboard?
- Should the home screen lead with the next quest or the latest activity reward?
- How much of the skill tree belongs on one mobile screen?

## Integration and privacy

- Which provider should be implemented first after the mockup phase?
- What data does the app truly need to retain?
- How should sync failures and stale data be explained without creating anxiety?
